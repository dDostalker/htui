# 教程 4.1：JS 和 Rust 绑定

Rust 应用逻辑通过**宿主函数**暴露给页面：注册后即为 JS 可直接调用的全局
函数。参数与返回值自动做类型转换，页面 JS 与 Rust 之间不出现任何手动封送。

> **依赖说明**：只需 `htui = "0.1"` 一个依赖。所有宏（`command` / `commands` /
> `IntoJs` / `FromJs`）都由 `htui` 重导出，宏展开的代码也只引用 `::htui::…`
> 路径——`htui-macros` 是实现细节，随 `htui` 传递引入，不要直接依赖它
> （避免与 `htui` 内部版本错配）。

## `#[htui::command]`：单函数绑定

普通 Rust 函数加上宏，即生成一个 `<fn>_command()` 构造器（返回
`HostFn`），注册进 `EventBindings` 后成为 JS 全局：

```rust
use htui::{Session, events::EventBindings};

#[htui::command]
fn greet(name: String) -> String {
    format!("hello {name}, greetings from Rust!")
}

fn main() {
    let mut bindings = EventBindings::default();
    bindings.command("greet", greet_command());

    let mut session = Session::new();
    session.set_bindings(bindings);
    session.render(
        r#"
        <p id="out"></p>
        <script>
          document.getElementById('out').textContent = greet('htui');
        </script>
        "#,
        "",
    );
}
```

参数类型需实现 `FromJs`（基础类型、`Option`、`Vec`、结构体均可），返回类型
需实现 `IntoJs`。结构体直接派生：

```rust
#[derive(htui::IntoJs)]
struct UserInfo {
    name: String,
    level: u32,
}

#[htui::command]
fn current_user() -> UserInfo {
    UserInfo { name: "ada".into(), level: 3 }
}
// JS: var u = current_user(); u.name; u.level;
```

用 `name = "…"` 指定 JS 侧的注册名（如驼峰命名）：

```rust
#[htui::command(name = "formatDateTime")]
fn format_datetime(secs: u64) -> String {
    format!("@{secs}")
}
// JS: formatDateTime(42)
```

## `#[htui::commands]`：模块批量注册

模块内每个 `#[htui::command]` 自动生成 `register(&mut EventBindings)` 和
`js_bindings()`（带 JSDoc 的样本 JS 接口，供代码分析器识别）：

```rust
use htui::events::EventBindings;

#[htui::commands]
mod app {
    /// 按函数名注册。
    #[htui::command]
    pub fn greet(name: String) -> String { format!("hello {name}") }

    /// 按显式 JS 名注册。
    #[htui::command(name = "formatDateTime")]
    pub fn format_datetime(secs: u64) -> String { format!("@{secs}") }
}

fn main() {
    let mut bindings = EventBindings::default();
    app::register(&mut bindings);
    // …
}
```

## 有状态命令

返回 `HostFn` 的零参数命令即为有状态命令：闭包捕获的状态在多次 JS 调用间
存活。闭包用 `htui::script::host_fn` 构造，函数体内不出现任何 Boa 类型：

```rust
use htui::script::HostFn;
use std::sync::{Arc, Mutex};

#[htui::command(name = "sample")]
fn sample() -> HostFn {
    let calls = Arc::new(Mutex::new(0u64));
    htui::script::host_fn(move |ctx| {
        let mut n = calls.lock().unwrap();
        *n += 1;
        let mut obj = ctx.object();
        obj.set("n", *n);          // JS: sample().n
        Ok(obj)
    })
}
```

`host_fn` 闭包的 `ctx: HostCtx` 提供 `arg` / `arg_required`（取参）、
`event`（当前事件）、`object`（构造 JS 对象）。返回 `Err(HostError)` 会映射
为 JS 异常。

## 线程模型：宿主函数阻塞只拖住脚本线程

宿主函数运行在**脚本线程**上。一个阻塞的宿主函数（比如等后台采样）只会
冻结页面 JS——滚动、缩放、拖选、退出照常响应。重活应当放后台线程，宿主
函数只读 `Arc<Mutex<Snapshot>>` 快照：

```rust
// 后台线程持续采样；宿主函数只读快照，永不阻塞输入。
#[htui::command]
fn cpu_usage() -> f32 {
    SNAPSHOT.lock().unwrap().cpu
}
```

周期刷新由页面 JS 用 `setInterval` 驱动（监控器每 200ms 调一次
`sample()` 即可）。

## 错误与调试

- JS 调用不存在的全局：ReferenceError，仅告警不崩溃（对齐浏览器）；
- 宿主函数返回 `Err`：JS 侧抛异常，可用 `try / catch` 捕获；
- `console.log / warn / error` 经 `log` 门面输出；`alert` 弹终端提示；
  `quit()` 直接退出引擎。
