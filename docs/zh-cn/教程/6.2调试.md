# htui 调试

> 本文面向正在用 htui 开发终端界面的作者。调试手段按"先看日志、再热重载、
> 最后排查常见坑"的顺序组织。日志契约（记录器接入、`console.*` 的 target
> 约定、release 级别裁剪）见 [5.日志.md](5.日志.md)，本文不重复。

---

## 1. 让日志可见

htui 自身不装记录器，宿主先接一个 `log` 实现才能看到引擎内部输出：

```rust
env_logger::Builder::from_env(env_logger::Env::default()).init();

let mut session = htui::Session::new();
session.render(&html, &css, &js);
```

开发期建议 `RUST_LOG=debug`：

| 现象 | 看什么 |
| --- | --- |
| CSS 声明没生效 | `debug` 级别里 CSS 解析器的报错（无效值会被整条丢弃而不是猜） |
| 资源没加载（`<script src>` / `<img>` / fetch） | `mem://` 注册表命中的 debug 日志 |
| JS 抛错 / 引用未定义 | 脚本层的 warn（对齐浏览器 ReferenceError 失败模式，不崩溃） |
| JS 的 `console.log` | `RUST_LOG=console=info` 单独过滤 |

注意 release 构建（`log` 的 `release_max_level_warn`）下 `debug!` / `info!`
整体消失，`console.log` 也随之不可见——排查问题时用 debug 构建。

## 2. 热重载（debug 构建自动启用）

`include_html!` / `include_css!` / `include_js!` 在 **debug 构建**里会携带
源文件路径。满足以下两个条件时，`Session::render` 自动进入热重载模式：

1. 三个源都来自真实文件（`include_str!` 内联字符串不带路径，无从监视）；
2. `Config::events` 为 `true`（事件循环在跑）。静态渲染（`events = false`）
   下会记录一条 warn 并回退普通渲染。

监视器每 200ms 先比对元数据（大小 / 修改时间），签名变化后才读文件，并再等
一个轮询确认签名稳定——编辑器的半写入状态不会触发重载。HTML / CSS / JS
任意一个文件变化都会整页重载（重新解析 + 重跑脚本）。

典型工作流：`cargo run` 起一次，然后只改 `player.css` / `player.html`，
终端里即时看效果；改 Rust 代码才需要重新编译。

Esc 退出（内置按键全集见 [4.0动态终端.md](4.0动态终端.md)）。

## 3. panic 时的终端状态

htui 安装了 panic 钩子：任何线程 panic 时先恢复终端（退出 raw mode、备用
屏幕、鼠标捕获、括号粘贴，重新显示光标），再走默认钩子并把 panic 消息与
位置写进 `log::error!`。

也就是说：

- panic 后终端**不会**停留在乱掉的 raw-mode 状态，报错可以直接读；
- 但 panic 信息走的是 `log`，**没接记录器就什么都看不到**——调试期务必接上
  记录器（见第 1 节）；
- 正常退出路径（Esc / `Quit` 命令）与 panic 共用同一套恢复逻辑，不会双重
  恢复。

## 4. 常见排查清单

| 症状 | 检查 |
| --- | --- |
| 整页空白 / 布局不动 | `Config::events` 是否按预期；JS 是否真的改了 DOM（`console.log` 确认） |
| 样式不生效 | 属性是否在引擎支持列表（见 [能力差异清单](../能力差异清单.md)）；无效值会被**整条丢弃**——把声明拆成单条逐个试 |
| `<img>` / `<script src>` / fetch 加载失败 | 资源是否注册进了 `mem://` 会话注册表，路径前缀拼写是否一致（前缀可选但要一致） |
| 媒体查询没命中 | `@media` 的单位是**终端格**（`1ch` = 1 列），不是 CSS 像素；`@media` 与 JS `matchMedia` 共用同一套解析 |
| JS 完全不执行 | 是否静态渲染（`events = false` 不跑事件循环）；`<script src>` 的资源是否注册 |
| 界面卡死但还能按键 | 宿主函数在脚本线程执行——重活应放后台线程，只读快照（见 [4.1JS和Rust绑定.md](4.1JS和Rust绑定.md)） |

## 5. 观察渲染结果本身

`TermLayout`（`tui::graph_api`）可以直接在测试里驱动：构造 `TermMap` 给定
列数 / 行数，`draw(&arena, root_id, &term_map)` 后读 `layout: Vec<Block>`
逐格断言。测试目录（`crates/htui/tests/layout_*_tests.rs`）大量使用这一
模式，是排查"为什么画成这样"的最直接工具——不依赖真实终端。
