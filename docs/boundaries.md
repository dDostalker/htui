# htui 边界文档（Boundaries & Scope）

> 本文档定义 htui **做什么**、**不做什么**，是所有功能决策的最高判据。
> 与 `AGENTS.md`（行为契约）、`docs/script-layer.md`（脚本层）配套阅读。

---

## 1. 使命

**把 Web 开发带给终端**：让会 HTML / CSS / JS 的人，不学任何 TUI 框架，
就能在终端里写出带布局、交互和脚本的界面。

htui 用 Rust 写终端 UI 的又一种方式"。

## 3. 核心承诺（必须做对）

以下能力是 htui 存在的理由，优先级最高，永远不得为便利性牺牲：

1. **HTML/CSS 子集按浏览器语义工作**：级联、盒模型、flex、块边界换行、
   选择器（含 `:hover`）行为与浏览器一致，不允许"差不多就行"的近似。
2. **脚本层闭环**：JS 操作 live DOM + 事件（`click` / `hover` / `focus` /
   `blur` / `input` / `change`）+ 宿主函数（`#[htui::command]`）是完整可用的，
   不是 demo 摆设。
3. **交互开箱即用**：点击、hover、输入框编辑、拖选（流式 + 框选）、剪贴板。
4. **性能有预算**（见 §7）：交互要跟手，动态页面刷新不掉帧。
5. **调试体验**：错误信息定位到 HTML/CSS 的来源，`--dump` 可无终端预览，
   日志可追踪。
6. **可无头测试**：核心逻辑不依赖真实终端。

## 4. 明确不做（拒绝清单）

以下内容**永不进入**范围，除非边界文档被显式修订：

| 拒绝项 | 理由 |
| ------ | ---- |
| CSS 动画 / 过渡 / `transform` / `opacity` | 终端无时间轴与像素语义，做了就是永无止境的追赶 |
| 完整 CSS（`calc()`、变量、媒体查询、完整 grid 等） | flex 的 `gap` 已实现；其余按需逐项评估，不整体承诺 |
| 完整 JS 语义（完整 Web API、网络/文件系统访问、`XMLHttpRequest`/`WebSocket` 等） | Boa 提供基础；`fetch` 已支持 `mem://` 注册表 + Promise 微任务队列（见 `web-support.md` §3.2），但**不访问网络与文件系统**，浏览器级网络栈不在范围 |
| 像素级渲染（除 `<img>` 光栅化） | 终端是字符网格，像素渲染偏离使命 |
| 浏览器 devtools | 使用配套自带工具 |
| 多文档并行 / 窗口管理 | 单文档会话是当前模型 |
| 无障碍 / 屏幕阅读器 | 不做承诺 |
| 触摸 / 移动端 | 不做承诺 |
| 服务端渲染（浏览器中预览 htui 页面） | 未来可能的独立工具，**不是引擎内核**的职责 |

## 6. 与浏览器的对齐层级

- **完全对齐（必须）**：文本布局与换行、CSS 级联、盒模型、事件语义、
  选择/复制的块边界换行、`on*` 属性编译语义。用户不应感知差异。
- **有意识偏离（可接受）**：渲染是字符网格而非像素；行内布局为近似；
  字体以"单元格"为单位；
- **不承诺（明确告知用户）**：视觉像素、动画、完整 Web API、媒体查询。
  遇到不支持的语法，**报出清晰错误**而非静默渲染错。

## 7. 性能边界

- 交互（点击 / hover / 拖选）：单帧增量渲染目标 **< 5ms**（区域重绘路径）。
- 动态页面（`setInterval` 刷新）：刷新间隔 ≥ 100ms 时不应掉帧；
  "值未变不触发渲染" 与命令合并是必须机制，不是优化选项。
- 每次渲染线程全量重绘是最后手段，任何新特性不得默认走全量路径。
- 布局 / 绘制 / 提取逻辑应可无头基准（`benches/`）。

## 8. 功能决策准则

新增功能（标签、CSS 属性、JS API、交互）时，逐条对照：

1. **使命**：服务于"终端 Web 开发"吗？如果是纯 Rust 库便利性，拒绝。
2. **对齐**：能按浏览器语义实现吗？不能则明确偏离并文档化，绝不"半对齐"。
3. **性能**：最坏情况下每帧成本是否在 §7 预算内？
4. **可测**：能写无头测试吗？不能则重新设计。
5. **拒绝清单**：是否已被 §4 覆盖？被覆盖则拒绝。
6. **维护成本**：单人可维护吗？新子系统（如完整 grid）若无持续投入计划，
   保持预留状态。

## 9. 边界变更流程

- 任何"引入 §4 拒绝项"或"改变 §6 对齐层级"的决定，必须：修改本文档 →
  同步 `AGENTS.md` → 同步相关实现与测试。
- 边界文档是行为契约的一部分，LLM 与本项目交互时以此为最高参考之一。
